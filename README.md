# ⛅ skala-vue

SK AX Full-Stack Engineering 과정의 Vue.js 실습 프로젝트입니다.

날씨 대시보드 하나를 계속 고쳐 나가는 방식으로 진행했습니다. 처음엔 배열을 하드코딩한 목업이었고, 여기에 computed와 watch를 붙이고, 컴포넌트로 쪼개고, 라우터와 Pinia를 얹고, 마지막에 OpenWeatherMap 실 API로 갈아끼웠습니다. **단계별 결과물은 지우지 않고 남겨뒀기 때문에** 과제 단계 메뉴에서 순서대로 비교해볼 수 있습니다.

Vue 3(Composition API), Vue Router 5, Pinia 3, Axios로 만들었고 빌드는 Vite를 씁니다.

## 실행 방법

```bash
npm install
npm run dev
```

| 명령어 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm run build` | 배포용 정적 파일 생성 |
| `npm run lint` | Oxlint + ESLint 검사 |
| `npm run format` | Prettier 정렬 |

## 🔑 API 키 설정

실제 날씨 데이터를 받아오려면 키가 필요합니다. 프로젝트 루트에 `.env.local` 파일을 만들고 OpenWeatherMap에서 발급받은 키를 넣어주세요.

```
VITE_WEATHER_API_KEY=여기에_키
```

몇 가지 주의할 점이 있습니다.

- Vite는 **`VITE_` 로 시작하는 변수만** 클라이언트 코드로 넘겨줍니다. 접두사를 빼먹으면 `undefined`가 나옵니다.
- `.env.local`은 `.gitignore`의 `*.local` 규칙에 걸려서 저장소에 올라가지 않습니다.
- 키를 새로 발급했다면 활성화까지 시간이 걸립니다. **401이 뜬다고 키가 틀린 게 아닐 수 있으니** 조금 기다렸다가 다시 시도해보세요.

## 과제별 구현 내용

### 과제 1 — 날씨 목업

`v-for`로 카드를 반복해서 그리고 `:key`에는 id를 넣었습니다. 인덱스를 key로 쓰면 중간에 항목이 지워질 때 엉뚱한 DOM이 재사용된다고 해서 그렇게 했습니다.

25도를 기준으로 `v-if`/`v-else`로 더움과 선선함 뱃지를 나눴습니다. 검색창은 **일부러 `v-model` 대신 `:value` + `@input`으로 직접 구현**했는데, 이 둘을 합친 게 결국 `v-model`이라는 걸 확인해보고 싶었기 때문입니다.

카드를 누르면 상태바가 바뀌고 상세보기 버튼을 누르면 알림창이 뜹니다. 그런데 버튼 클릭이 카드 클릭까지 타고 올라가는 문제가 있어서 `@click.stop`을 붙여 막았습니다.

### 과제 2 — Composition API

검색 필터를 `computed`로 만들었습니다. 처음엔 `ref`로 필터링된 배열을 따로 두고 검색어가 바뀔 때마다 수동으로 갱신할까 했는데, computed를 쓰면 **의존하는 값이 바뀔 때만 알아서 다시 계산되고 캐싱까지** 됩니다.

`watch`로는 상태바 문구가 바뀔 때 로그를 남겼고, `watchEffect`로는 검색어를 추적했습니다. 둘의 차이가 헷갈렸는데, **watchEffect는 감시 대상을 안 적어도 안에서 쓴 값을 알아서 추적하고 처음에 한 번 즉시 실행된다**는 게 가장 큰 차이였습니다.

이후 실습에서 deep watch와 multi-source watch도 따로 만들어봤습니다. deep을 켜면 객체 안쪽 변경까지 잡히긴 하는데 **이전 값과 새 값이 똑같이 나와서 과거 추적이 안 됩니다.** 속성 하나만 화살표 함수로 집어서 감시하면 이전 값이 살아있습니다.

### 과제 3 — 컴포넌트 분리

기능은 그대로 두고 파일만 4개로 쪼갰습니다. `WeatherParent`가 상태를 전부 들고 있고 나머지는 표시만 담당합니다.

`BaseDashboardCard`는 안에 슬롯만 두고 테두리와 여백만 담당합니다. 검색 박스든 리스트 박스든 이걸로 감싸면 되니까 중복이 줄었습니다.

`SearchBar`와 `WeatherCard`는 props로 값을 받고 emits로 이벤트를 올려보냅니다. **props가 읽기 전용이라 자식이 직접 못 바꾸는 게** 처음엔 불편했는데, 데이터가 어디서 바뀌는지 추적하기 쉬워진다는 점에서 납득이 갔습니다.

여기서 쪼개둔 컴포넌트는 과제 4의 `WeatherHomeView`에서 그대로 재사용했습니다.

### 과제 4 — Router

라우트를 정의하고 자주 들어가지 않는 페이지에는 지연 로딩을 걸었습니다. 404 처리를 위한 catch-all 라우트는 **위에서부터 매칭되기 때문에 반드시 목록 맨 아래**에 둬야 합니다.

상세보기를 누르면 원래 `alert`이 떴는데 `router.push`로 바꿔서 실제 페이지 이동이 되게 했습니다.

추가로 **검색어를 URL 쿼리스트링과 동기화**했습니다. watch로 검색어가 바뀔 때마다 `router.push`로 주소를 갱신하고, `onMounted`에서 `route.query.search`를 읽어 상태를 복원합니다. 이렇게 하면 검색한 상태로 새로고침하거나 링크를 공유해도 검색어가 유지됩니다.

과제 단계와 실습 모음 라우트도 직접 추가했습니다.

### 과제 5 — Pinia

온도 단위를 섭씨와 화씨로 바꾸는 기능입니다. 단위를 바꾸는 토글 버튼은 네비게이션 바에 있고 실제로 온도를 보여주는 건 카드와 상세 페이지인데, **이 둘은 부모-자식이 아니라 사촌 관계**입니다. props로 넘기려면 중간 컴포넌트들이 전부 배달만 하는 신세가 되기 때문에 스토어를 썼습니다.

설계에서 신경 쓴 부분이 하나 있습니다. **원본 데이터는 항상 섭씨로 두고 화면에 그릴 때만 변환**합니다. 스토어에 변환된 값을 저장해버리면 25도를 기준으로 더움과 선선함을 판정하는 뱃지 로직이 깨집니다. 화씨로 바꾸면 82라는 숫자가 25보다 크니까 전부 더움이 되어버리기 때문입니다.

### 과제 6 — Axios

`axios.create`로 인스턴스를 만들어서 `appid`, `units`, `lang` 같은 공통 파라미터를 한 곳에 모았습니다. 매번 URL에 붙이지 않아도 되니 편합니다.

응답을 그대로 컴포넌트에 넘기지 않고 **`normalize` 함수를 거치게** 했습니다. OpenWeatherMap 응답은 `raw.main.temp`, `raw.weather[0].description` 같은 식으로 중첩되어 있는데, 이걸 그대로 넘기면 API가 바뀔 때마다 컴포넌트를 전부 고쳐야 합니다. 앱에서 쓰는 모양으로 한 번 번역해두면 컴포넌트는 건드릴 일이 없습니다.

로딩 상태와 에러 메시지를 따로 두고 `try-catch-finally`로 처리했습니다. **finally에 로딩 종료를 넣은 건 에러가 나도 스피너가 멈추게** 하기 위해서입니다. 에러는 401인지 타임아웃인지에 따라 다른 안내가 나가도록 나눴습니다.

요구사항 2번으로 OpenWeatherMap의 대기오염 API를 붙여 미세먼지를 표시했고, 3번으로는 Open-Meteo를 연동해 5일 예보를 넣었습니다. Open-Meteo는 서버가 다르니 axios 인스턴스를 따로 만들었습니다. 응답이 날짜 배열, 최고기온 배열, 최저기온 배열이 따로 오는 형태라서 인덱스로 짝지어 객체 배열로 바꿔야 했습니다.

호출 순서도 신경 썼습니다. **대기오염과 예보는 서로 상관없으니 `Promise.all`로 동시에** 보내고, 좌표가 필요한 요청은 날씨 응답을 받은 다음에 순차로 보냅니다.

## 😵 삽질 기록

- **켈빈** — `units=metric`을 안 넣으면 온도가 301처럼 나옵니다. 켈빈이 기본값이라는 걸 몰라서 한참 헤맸습니다.
- **스토어 구조분해** — `const { unit } = useConfigStore()` 로 꺼냈더니 버튼을 눌러도 화면이 안 바뀌었습니다. 구조분해하는 순간 반응형 상자에서 값만 복사돼 나와서 연결이 끊깁니다. `configStore.unit` 처럼 점 표기법으로 접근해야 합니다.
- **`defineProps` 반환값** — 템플릿에서만 쓸 땐 그냥 `defineProps({...})` 해도 되는데, script 안에서 쓰려면 `const props = defineProps({...})` 처럼 변수로 받아야 합니다.
- **null 가드** — `cityData`가 `ref(null)`로 시작하는데 computed 안에서 바로 `.temp`를 읽었다가 터졌습니다. 템플릿의 `v-if`와 computed는 별개로 평가됩니다.

## 아쉬운 점

온도 변환 로직이 `WeatherCard`와 `WeatherDetailView` 두 군데에 거의 똑같이 들어가 있습니다. 예보에도 단위 변환을 적용하려면 세 번째 중복이 생깁니다. **composable로 빼면 깔끔해질 것 같은데** 이번 범위는 아니라서 남겨뒀습니다.

다크 모드는 지원하지 않습니다. 컴포넌트들이 전부 밝은 배경을 기준으로 짜여 있어서, 스캐폴딩에 딸려오던 `prefers-color-scheme` 설정을 꺼두고 라이트 테마로 통일했습니다.
